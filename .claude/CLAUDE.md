# CLAUDE.md

Голосовий мод Claude Code (`voice-mod`). Відповіді власнику — українською.

## Розкладка

Корінь репозиторію = тека мода: `.claude-plugin/plugin.json` і поруч `marketplace.json`
(маркетплейс `claude-code-voice-mod`, `source: "./"`), `hooks/` (TypeScript-хуки),
`listener/` (Python-слухач), `types/` (контракт `$.state`), `dev/` (перевірки й заміри).
`README.md` — англійською, з розділом «What it runs, sends and downloads» (каталог його
вимагає), `README.uk.md`, `PRIVACY.md`, `LICENSE`. Зміни поведінки дописувати в обидва
README, а якщо міняється, що мод надсилає чи зберігає, — у PRIVACY.md. Особисте власника
(словники, підказки) сюди НЕ пишеться: репозиторій публічний.

## Публікація

- Встановлення: `/plugin install voice-mod --marketplace Parsec1498/claude-code-voice-mod`.
- Каталог Anthropic: портал https://claude.ai/directory/manage → Submit new → Plugin bundle
  (план Pro+). Чекліст: https://claude.com/docs/plugins/pre-submission-checklist — README ≥ 40
  слів і опис усього, що мод запускає/надсилає/качає; ліцензія; не-зображення < 256 KiB,
  ≤ 512 файлів, без symlink/submodule/LFS; ім'я не `claude-*`. Перед подачею:
  `claude plugin validate --strict .`. Іконки поки нема.
- Ім'я плагіна `voice-mod` — і ключ стану (`atom({ plugin: 'voice-mod' })`, `PluginState`
  у `types/index.d.ts`), і префікс інструмента `mcp__voice-mod__add_term`: міняти разом.

## Як мод вантажиться під час розробки

Локальний маркетплейс із цієї теки (`claude plugin marketplace add D:\Dev\claude-code-voice-mod`
+ `claude plugin install voice-mod@claude-code-voice-mod`): Claude Code читає мод прямо з теки,
правка доходить до сесій лише на `/reload-plugins`. Свідомо не `CLAUDE_CODE_PLUGIN_DIRS` +
`CLAUDE_CODE_PLUGIN_DIR_WATCH=1` — там кожне збереження перезавантажувало мод у ВСІХ чатах.
Слухач (`listener.py`) перезавантаженням мода не чіпається — для нього ↻ у ⚙ (або `restart`
у control.json).

## Перевірки (з теки мода)

```powershell
claude plugin validate .
claude plugin test .                                     # тести хуків і UI
npx -y -p typescript@5.6.3 tsc -p .                      # типи (після першого завантаження мода)
py -3.14 -m ruff check --select E9,F,B listener dev
powershell -File dev/modes_check.ps1                   # режими слухача на синтезованих фразах
powershell -File dev/listener_check.ps1                # життєвий цикл слухача (detach, mute, restart, підміна моделей, збій вибору, озвучення)
& "$env:USERPROFILE\.claude\voice-mod\venv\Scripts\python.exe" dev/words_check.py   # чисті функції слухача (стоп-слово, скасування, моделі, speech.py)
```

Озвучення перевіряється так:
- `hooks/speak.test.ts` (у `plugin test`) — пошук і чистка блоку, мова, каталог голосів, розділ
  промпту; `hooks/voice.test.ts` — `prompt.compose`, `speak.json` на `turn.complete`, `stop`.
- `dev/words_check.py` ганяє `listener/speech.py` без Piper і мережі: URL голосів, `fresh_request`,
  `deaf`/`speak_action`, `Speaker` і `TtsInstaller` на підставному `tts\` (venv `--without-pip` з
  фейковим `piper/__main__.py`, локальний HTTP-сервер замість HF), хвіст глухоти від миті, коли
  звук справді обірвано, `DEFAULT_VOICE` проти `hooks/speak.ts`, відсутність `import piper` і
  `piper1-gpl` у `listener/*.py`.
- `dev/listener_check.ps1` — розділ «озвучення»: справжнє `ttsInstall` у тимчасовій теці →
  `installing` → `ready`, `speak.json` → `speaking` → `ready`, ✖ і mute обривають, Piper — окремий
  процес і після виходу слухача його нема, старий `at` і ↻ не озвучують удруге, битий `.onnx` →
  `error`, `ttsRemove` стирає `tts\`. Готовий `tts\` кешується в `%TEMP%\voice-dev\tts-cache`
  (перший прогін качає Piper і голос ~140 МБ, далі `ttsInstall` іде з кешу за ~6 с). Крок «SAPI
  вголос під час speaking» пропускається (`SKIP`), якщо живий слухач власника слухає мікрофон
  (інакше фраза з активатором могла б стати командою в його чаті) — для повної перевірки вимкніть 🎤.
  Українську озвучку й вибір голосу на слух перевіряє власник наживо.

`dev/measure_models.py` — не перевірка, а заміри пам'яті моделей для `hooks/models.ts`
(VRAM на CUDA, RAM на CPU, диск; докачує бракуючі моделі в `hf\`); числа в каталозі
міняти лише з нього.

`claude` у застосунку на ПК — не в PATH: `%LOCALAPPDATA%\Claude-Data\claude_*\claude-code\<версія>\claude.exe`
(версія міняється з оновленнями — шлях живого процесу: `Get-Process claude | Select Path`). Синтезоване мовлення — лише англійське (SAPI Zira), тому dev-скрипти
ганяють слухача з `language: en` у тимчасовому `control.json` (як і живий мод); українським
голосом перевіряє власник наживо.

## Як влаштований

**Дві частини.** Хуки мода (`hooks/register.tsx`, TypeScript, рушій модів) і слухач
(`listener/listener.py`, окремий Python-процес). Обмін — файлами в
`%USERPROFILE%\.claude\voice-mod\`:

- `bus.json` — стан слухача + останні 40 подій з наскрізним `seq` (пише слухач, серцебиття
  раз на 1 с). Поля: `device` (`cuda`|`cpu`), `models` (імена моделей, що вже на диску),
  `msg` (під час докачки — `⬇ <модель>: X ГБ`; під час встановлення озвучення — крок і МБ),
  `tts` (`absent|installing|ready|error` — модуль озвучення; стартове значення `ready`, якщо
  `tts\installed.json` і python venv на місці), `voices` (імена голосів Piper, що вже на диску:
  `.onnx` + `.onnx.json`, без `.part`). Стани: окрім наведених у `state` — `speaking` (`msg` —
  текст, що звучить). Види подій: `ignored`, `part` (проміжна
  фраза диктовки і голе стоп-слово — в 🕘 блідо, видно, що почуто замість «Роби»),
  `cancelled` (команду скасовано словом чи кнопкою ✖; порожній текст — голе «Клоде, відміна»:
  мод відхиляє висячу картку), `spoke` (озвучено блок «🔊»; `text` — що сказано; в 🕘 блідо),
  `command`, `info`, помилки;
- `control.json` — mute, safeMode, `restart` (мс), `cancelAt` (мс, натиск ✖), `ttsInstall` і
  `ttsRemove` (мс, кнопки модуля озвучення) — усі чотири мітки, як `restart`, не налаштування й не
  міняють `version`, а старші за запуск слухача — ігноруються — і налаштування ⚙,
  спільні для всіх сесій (порожнє/невідоме значення = типове):
  - `language` `uk`(типово)|`en`; `beep` `off|wake|end|both`; `autoEnd` (false — до стоп-слова);
  - `wake`, `stop`, `cancel`, `prompt`, `hotwords` — рядки; порожні = типові слова/підказка
    вибраної мови (`cancel`: «відміна» / «cancel»);
  - `chat` — фраза зміни чату (через кому); порожньо = «Зміна чату» / «Switch chat»;
  - `wakeModel`, `model` — назви faster-whisper (мала/велика); порожньо = типова для пристрою;
  - `filterMode` `off|both`(типово)`|clean`; `filterModel` `haiku`(типово)`|sonnet`;
    `filterTimeoutMs` `3000|6000`(типово)`|10000`; `filterSystem` — своя системна інструкція
    фільтра (порожньо = типова мови, `defaultFilterSystem`; збережена без змін типова пишеться
    як порожнє); `filterNotes` — рядок, дописується в кінець інструкції (своєї чи типової);
    перед ним — абзац зі словами-підказками (`hotwords`): модель виправляє написання термінів;
  - `autoTerms` — агенти самі додають правила в словник (типово true);
  - `speak` — озвучувати відповіді (типово false; слухач бере лише `=== true`); `speakVoiceUk`,
    `speakVoiceEn` — голос Piper мови (`uk_UA-…`, `en_US-…`); порожньо чи не за схемою
    `<код>-<голос>-<x_low|low|medium|high>` = типовий (`DEFAULT_VOICE`). `speak` і голоси —
    налаштування (входять у `version`);
- `owner.json` — яка сесія отримує команди (`session`, `at` — пульс раз на 2 с, `locked`,
  `handoff` — команда, передана зміною чату, `why` — `typed|button|voice|first`, причина
  для сповіщень); `alive-<session>.json` — пульс сесій (раз на 5 с; `ref` і `title` — як цей
  чат називає ListAgents, оновлюються раз на 2 хв; слухач дивиться лише на час зміни файлу);
- `speak.json` — запит на озвучку (пише мод, читає слухач за `mtime`): `{ seq, at, text, lang,
  voice, session }` або `{ seq, at, stop: true, session }`; `at` — мс, `seq = at` (росте й тоді,
  коли пишуть різні сесії); `lang` — `uk|en`, `voice` — назва голосу;
- `glossary.txt` — особистий словник; там же `venv\` і `hf\` (моделі), `tts\` (модуль
  озвучення: `venv\`, `voices\`, `installed.json`) і журнали `tts.log` (встановлення, pip) та
  `speak.log` (stderr Piper).

**Слухач один на машину** (mutex `Local\ClaudeVoiceListener`, другий виходить з кодом 3).
Запускається ВІДВ'ЯЗАНО (`--detach`: `CREATE_NO_WINDOW | NEW_PROCESS_GROUP`, БЕЗ
`DETACHED_PROCESS` — з ним exe-обгортка venv лишалась без консолі, а справжній python
відкривав видиме вікно): дочірній процес мода гине з модулем, а моделі вантажаться
~20 с. Сам виходить: 2 хв без жодного пульсу сесій, 60 с вимкненого мікрофона
(`--muted-exit`), `restart` у control.json. Поки мікрофон вимкнено, мод слухача НЕ
піднімає.

**Розпізнавання.** faster-whisper; `--device auto`: CUDA (колеса nvidia-cublas-cu12 +
nvidia-cudnn-cu12 у venv, `add_cuda_dlls`) → small (активатор/чернетки) + large-v3
int8_float16 (~2.4 ГБ VRAM); без CUDA — base + large-v3-turbo int8. Мала модель на GPU
~130 мс на 0.5–1.2 с звуку і на КОРОТКИХ шматках чує активатор надійніше, ніж на 2 с —
тому ранні перевірки на 0.5/0.8/1.1/1.5/2.0/2.5 с мови. Відкинуто з вимірами:
turbo (зациклювався на підказці), base як активатор (чув «Клоде» як «Лода» — тепер
«лоде/лода/лоді» у дефолтних варіантах), NPU Intel AI Boost через OpenVINO (компіляція
252 с, зациклення, підказка валить конвеєр), OpenVINO на NVIDIA (повільно).

**Мова.** `language` у `control.json` керує ВСІМ: інтерфейсом мода (`hooks/i18n.ts`, у т. ч.
описи slash-команд — реєструються наново), мовою whisper, типовими активатором/стопом/підказкою
(uk: «Клоде»/«Роби»; en: Claude/Done), повідомленнями слухача (`LANG`) і системною інструкцією
фільтра. Діє з наступної фрази, без перевантаження моделей — крім випадку, коли вибрано
англійські моделі (`*.en`, `distil-*`): тоді зміна мови перевантажує моделі (при `uk` вони
ігноруються, при `en` повертаються). Свої слова/підказка від мови не залежать.

**Вибір моделей.** Каталог — `hooks/models.ts` (якість ★ окремо для uk/en — орієнтовна, з
опублікованих WER; пам'ять — виміряна `measure_models.py`); у ⚙ списки відсортовані за вагою,
не-встановлені з ⬇, вибір такої моделі = згода на докачку. Слухач сам зводить `wakeModel`/`model`
до пари (`resolve_models`) і підміняє її в тому ж процесі, ↻ не треба:
- підміна лише в тиші — не посеред фрази чи диктовки (`should_swap`); спершу вивантажити старі,
  потім вантажити нові (дві великі в 8 ГБ не влізуть), 10–30 с стан `loading`;
- нема на диску — докачка у фоновому дочірньому процесі (`Downloader`, `HF_HUB_OFFLINE=0` лише
  для нього; сам слухач живе з `=1`), поки розпізнаємо старими; розпочата докачка не
  переривається, підміна йде на останній вибір;
- вибрана пара не піднялась (OOM, битий файл, докачка) — стан `error` з причиною, а на ТОМУ Ж
  пристрої беруться типові (не CPU); винною пара визнається лише коли типові піднялись;
- англійські (`*.en`, `distil-*`) при `uk` ігноруються (беруться типові), але вибір у
  `control.json` лишається і повертається з `en`.

**Кінець команди.** Автозавершення — 700 мс тиші. Без нього — фрази копляться до
стоп-слова; кожна йде у велику модель ОДРАЗУ (з попереднім текстом у підказці), тож
після «Роби» лишається лише остання фраза (на довгій диктовці було до 12 с, стало
~0.5 с). Стоп-слово діє ЛИШЕ після повних 700 мс тиші — варіант «на паузі 160 мс»
обривав команду, коли слово траплялось посеред речення (знято рішенням власника
2026-10-20). Голе стоп-слово окремою фразою ≤1.5 с — без великої моделі. Стоп-слово
порівнюється без префікса («робити» не відправляє). Хвіст допускає неточний запис:
токен збігається зі стоп-словом, якщо довжина та сама ±1, перші три літери однакові і
схожість difflib ≥ 0.75 («робі», «роби.» — так; «робота», «роблю» — ні); довше слово, що
починається зі стоп-слова («робив», «робити»), не збіг. Відомі хибні збіги (ratio рівно
0.75 і ті самі три літери): «робо» → «роби», «dont» → «done»; закріплені в `words_check.py`.
Для активатора правило не змінене.

**Скасування.** Слово скасування (`cancel`, типово «відміна» / «cancel») у кінці фрази після 700 мс
тиші відкидає команду в обох режимах: зібрану диктовку, першу фразу, голе слово ≤1.5 с (без
великої моделі). Перевіряється РАНІШЕ за стоп-слово. Збіг — те саме правило хвоста, але з точною
довжиною (`WakeMatcher(exact_len=True)`): інакше «…все відмінно» скасовувало б команду; «відміно»,
«відміну» — так (відомий хибний збіг англ.: «cancer»). Слово додається в підказку розпізнавачу
поруч зі стоп-словом (без автозавершення). Кнопка ✖ на рядку (перша, лише в `armed`/`transcribing`/`speaking`; у `speaking` обриває озвучку)
пише `cancelAt`: слухач відкидає диктовку, фразу після раннього активатора, голе «Клоде» чи
результат великої моделі, що саме розпізнавався (перевірка перед `send`/додаванням у `texts`),
скидає сегмент і чергу кадрів; нічого не триває — лише запам'ятовує мітку. Подія `cancelled`,
сигнал кінця, у чат — нічого.

**Команда посеред ходу.** `$.prompt.submit` плагіна виконується лише коли сесія вільна, тож поки
йде хід ГОЛОВНОГО циклу (`turn.start`/`turn.complete` без `agentId`), команда стає в чергу
`midTurn` і доставляється як `context` результату найближчого виклику інструмента головного
циклу — не субагента, не власного виклику мода, не deny і не `isError` (перерваний Esc крок) —
з оформленням «🎙 Голосова команда людини, сказана під час твоєї роботи…». Доставка вмикає гвард
(`guarded`), примітка в 🕘 і тост. Що лишилось у черзі на `turn.complete` (і перерваному) — іде
`prompt.submit`. Підтвердження картки посеред ходу теж доходить так; одноразовий дозвіл на
точний виклик діє. Черга — модульна змінна: перезавантаження мода посеред ходу її губить.

**Озвучення відповідей (опційний модуль; `hooks/speak.ts`, `listener/speech.py`).** Агент пише блок
«для вуха», озвучується лише він; вимкнено — мод не змінюється ні на байт (ні розділу промпту, ні
файлів, ні завантажень).
- **Встановлення** — кнопка «⬇ Встановити озвучення» в ⚙ (натиск = згода) пише `ttsInstall`.
  `TtsInstaller` у слухача, у фоновому потоці: venv `tts\venv\` (з `sys._base_executable` — базовий
  Python, не venv слухача) → `pip install piper-tts==1.8.0` → голос мови `language` у
  `tts\voices\` (`.onnx.json`, потім `.onnx`, кожен через `.part` + `os.replace`) → пробний
  синтез → позначка `tts\installed.json`. Прогрес — `msg` у `bus.json`; `bus.tts`: `installing` →
  `ready` (мод сам вмикає `speak`, коли бачить перехід `installing → ready`) чи `error` з причиною
  (кнопка лишається, «Повторити»). Повторне встановлення пропускає наявний venv. `ttsRemove`
  (кнопка в «Розширені» → «Озвучення», разом пише `speak: false`): `stop`, `abort()` встановлення,
  `rmtree` усієї `tts\` (повтори); у гіршому разі — посеред встановлення — блокує головний цикл
  слухача до ~13 с. Логи `tts.log`/`speak.log` лишаються. Основні `install.ps1` і
  `requirements.txt` Piper НЕ згадують.
- **Межа GPL (не порушувати).** `piper-tts` — GPL-3.0-or-later, мод — MIT. Тому: Piper лише в
  окремому venv `tts\venv\`, лише після натиску кнопки, викликається ЛИШЕ як окремий процес
  `tts\venv\Scripts\python.exe -m piper -m <onnx> --output_raw` (текст — один рядок у stdin,
  сирий int16 — зі stdout); у `listener/*.py` НІКОЛИ `import piper` і жодного рядка з `piper1-gpl`
  (`words_check.py` це перевіряє); код Piper не копіювати, не збирати разом із модом, не
  вшивати в `install.ps1`/`requirements.txt`. Ліцензійний текст — у README (розділ «Spoken
  answers») і PRIVACY; змінюєте, що ставиться чи звідки, — міняйте їх разом.
- **Голоси** — каталог `VOICES` у `hooks/speak.ts` (ім'я, мова, ліцензія, розмір `.onnx`), лише з
  вільною ліцензією датасету: CC0, public domain, Apache-2.0, CC BY 4.0 (авторство CC BY — у
  README обох мов). Ніколи: `lessac`, `ryan`, `hfc_*`, `l2arctic`, `semaine`, голоси з «See URL».
  Ліцензію беремо з поля `License` у `MODEL_CARD` голосу на HF `rhasspy/piper-voices`; картки частини
  англійських голосів кажуть «Finetuned from … lessac/Ryan» — це питання до власника, у README
  зазначено лише, що картка про це каже. `DEFAULT_VOICE` (uk `ukrainian_tts-medium`, en
  `joe-medium`) тимчасовий — до прослуховування; живе і в `speak.ts`, і в `speech.py`
  (`words_check` звіряє). Докачка голосу — `ensure_voice` у тому ж фоновому потоці (URL —
  `voice_urls`, ім'я — лише `valid_voice`, бо з нього складаються шлях і URL); голосу нема на
  диску — подія `info` «качаю голос…», цей блок пропускається. Зміна `speakVoice*` при
  `tts == ready` одразу докачує.
- **Інструкція агенту** — хук `prompt.compose`: поки `speak` увімкнено, ОСТАННІМ розділом
  `{ id: 'voice-mod:speak', scope: 'session' }` (рушій вимагає id `<плагін>:<назва>`) іде
  `speakSection(language)`. Додається в УСІХ сесіях мода, не лише у власника: власник міняється
  часто, а кожна зміна системного промпту скидає кеш; текст незмінний, поки не змінились
  `speak`/`language`. Збій не йде в рушій (промпт лишається як був). Суть: блок — окремим абзацом
  наприкінці ЛИШЕ останньої відповіді ходу, рядок `🔊 Озвучити:` / `🔊 Speak:`, 1–3 речення до
  ~300 знаків, простий текст, блок одномовний.
- **Мод → слухач.** `turn.complete` головного циклу (`!e.agentId`, `reason === 'answer'`, не
  відповідь генератора словника) → `speakAnswer`: `findSpeakBlock` (ОСТАННІЙ рядок з маркером — з
  `🔊` чи без, з `**…**` чи без; усередині ``` пропускається; нема маркера — нічого не звучить) →
  `speak` увімкнено → ця сесія власник голосу (`owner.json`) → `cleanForSpeech` (markdown, URL,
  емодзі; ≤ 600 знаків, обрізка по межі речення) → `speakLang` (частка кирилиці серед літер ≥ 0.5
  — `uk`, інакше `en`; тож англійська відповідь звучить англійським голосом і при `language: uk`)
  → `speak.json`. `stop` пишуть: людина набрала повідомлення в чаті-власнику (`prompt.submit`;
  🎙-команди, відповіді на картки й черга `midTurn` озвучку НЕ обривають) і сесія, яка щойно стала
  власником голосу (озвучка належала попередньому).
- **Слухач** (`speech.py`; проводка — `tts_tick`/`poll_speak` у `listener.py`, `tts_tick` крутиться
  кожну ітерацію, і при вимкненому мікрофоні теж). `fresh_request`: новий `seq`, `at > 0`, `at` не
  старший за 60 с і не старший за запуск слухача (↻ не повторює блок); `stop` → `stop_speaking`;
  інакше — якщо `speak`, мікрофон увімкнено, `tts == ready` і голос на диску — `pending_say`.
  `speak_action(now, at, collecting)`: `say` / `wait` (іде диктовка чи розпізнавання великої
  моделі — озвучка чекає, не перебиває людину) / `drop` (від `at` минуло > 30 с; подія `info`).
  `Speaker.say` спершу `stop()` (новий блок заміняє поточний, а не стає в чергу), далі потік: новий
  процес Piper на кожен блок, читання `read1`, вирівнювання по int16, `sounddevice.RawOutputStream`
  (частота — `audio.sample_rate` з `.onnx.json`) відкривається на першому шматку; таймер 60 с
  убиває Piper; stderr Piper — у `speak.log`. Дочірні процеси без вікна (`CREATE_NO_WINDOW`) і
  з очищеним середовищем (`child_env`: без `VIRTUAL_ENV`, `PYTHONHOME`, `PYTHONPATH`,
  `__PYVENV_LAUNCHER__` — інакше базовий Python, запущений з venv слухача, вважав би себе ним).
  Стан `speaking` з хвостом тексту, подія `spoke`. Обривають: ✖ (`cancelAt`), mute, `speak: false`,
  `stop`, `ttsRemove`, вихід слухача (`finally`). Збій Piper/виводу — стан `error` на 5 с з
  рядком із stderr, потім знову `ready`.
- **Правило глухоти.** Слухач не повинен чути себе (анти-ціль: озвучка стає командою). Поки
  `Speaker.busy` і ще 300 мс (`DEAF_TAIL_S`) після того, як звук СПРАВДІ обірвано (`deaf_until =
  max(deaf_until, now + 0.3)` ПІСЛЯ `abort()`/`close()` потоку відтворення, а не від виклику
  `stop()` — потік дописує поточний шматок і драйвер має затримку; `stop()` додатково ставить
  `deaf_until` одразу, тож глухота починається миттєво), `deaf()` повертає true: кадри мікрофона
  викидаються, `seg.reset()`, черга кадрів чиститься, розпізнавання нема. Голосом озвучку
  обірвати не можна. Мікрофон чує динаміки (перевірено: без озвучки та сама фраза давала
  `ignored`), тож це правило — єдине, що тримає озвучку від команди.

**Безпека** (`hooks/safety.ts`). Шар команди: haiku чистить текст і ставить
`safe|confirm`, локальний список коренів страхує (невинне «прибери теку» він свідомо
не ловить — це робота шару дій). Шар дії — гвард `tool.call`: увімкнений (атом `guarded`,
переживає перезавантаження мода) від ходу, що почався з 🎙, до наступного повідомлення,
НАБРАНОГО людиною; ходи сповіщень, фонових задач і розкладу його не знімають. Руйнівне →
deny + картка: видалення (rm/ri/del/Remove-Item/`::Delete`/`-delete`, і в лапках),
git reset/clean/checkout -f/push --force|+гілка|--delete (з опціями перед підкомандою),
надсилання назовні (curl/iwr з тілом, gh gist/release/repo, npm publish; звичайний
`git push` — ні), DROP/DELETE, kill, format, schtasks/служби; захищені шляхи
(`PROTECTED_PATH`: `~/.claude` крім projects/plans/todos, `.mcp.json`, профілі
PowerShell, автозапуск, `.git/`) — у Write/Edit/NotebookEdit і в командах: голос не має
вимкнути власний захист через control.json; `run_in_background`, CronCreate/RemoteTrigger/
ScheduleWakeup/Workflow; MCP, що міняє права/налаштування/розклад чи надсилає. «Так» —
одноразовий дозвіл на ТОЧНИЙ виклик, 2 хв. Кнопка підтверджує лише ту картку, яку
малювала, і не раніше ніж через 1.5 с після її появи (картку могла підмінити нова дія).
Безпечний режим (дефолт): підтвердити голосом не можна — лише кнопкою, «так» у чаті
чи `/voice-confirm`. Список — чорний, тож не повний: у режимі bypass permissions він
єдиний бар'єр.

**Записи `owner.json` у межах сесії** — лише через `withOwner` (проміс-ланцюг): пульс,
claim, замочок і зміна чату інакше перетирали `handoff`. Тік не накладається на себе
(`isTicking`), `lastSeq` ставиться одразу після черги.

**Обробка команди.** `filterMode`: `off` — сирий текст одразу, модель не кличеться, ризик
лише з локального списку; `both` — очищене + «(розпізнано: «…»)», якщо відрізняється; `clean` —
лише очищене. Модель/тайм-аут/`filterNotes` — з `control.json`; після тайм-ауту чи збою — сирий
текст і локальна оцінка. Шар дій (`destructiveReason`, гвард `tool.call`) від режиму не залежить.
Сире завжди в історії 🕘.

**Власник голосу.** Сесія, де людина востаннє щось відправила (`why: typed`), натиснула
🎧 «Сюди» чи набрала `/voice-here` (`button`), або куди передали зміною чату (`voice`). Режим у
рядку власника — кнопка «🔓 Авто / 🔒 Закріплено» (і `/voice-lock`) — ставить `locked` в
`owner.json`: відправка в інших чатах власника не перехоплює, лише явне 🎧/`/voice-here`,
яке закріплення знімає. Закріпити може лише власник; пульс переносить `locked` і `why`;
власник замовк на 8 с (чат закрито) — закріплення зникає з ним. Інші чати показують назву
власника (атом `ownerTitle`, з його alive-файлу) у рядку, рядку стану й живому тексті
(«🎙 → «…»: »). Тік помічає зміну власника (`seenOwner`; старт і перезавантаження не
рахуються) і в КОЖНОМУ чаті дає тост і запис в 🕘 з причиною; голос «нікуди» — теж.

**Зміна чату (експериментально, `hooks/chats.ts`).** «Клоде, зміна чату <назва>, <команда>»:
фраза діє ЛИШЕ на початку команди (текст від слухача вже без активатора); посеред — звичайний
текст. Назви — з ListAgents (як у бічній панелі; рядок «This session is <назва> [ref]» — про
себе): кожна сесія раз дізнається свій `ref` і пише його в alive-файл; власник при команді питає
ListAgents наново й зіставляє назви з сесіями мода за `ref` (чат без свіжого alive — не кандидат).
Назва — повна чи початок довгої (від двох слів), схожість ≥ 0.75; двозначно чи не знайдено —
команда нікуди не йде. Власник пише в `owner.json` нового власника з `handoff` (закріплення
переходить разом із голосом); той забирає команду сам і прибирає `handoff`, а подію шини з
`handoff.seq` не обробляє — інакше команда пішла б двічі. Фільтр і картки — у чаті-отримувачі.
ListAgents кличеться лише коли `$.tool.check` каже `allow`: діалог дозволу щохвилини гірший
за відсутність функції. Перемкнути екран застосунку на той чат мод не може (API нема).

**UI.** Рядок стану — `AbovePrompt` (статус, сесія, останнє почуте: команда `✓`
кольором success, інше блідо; живий текст `🎙 …`), кнопки-гліфи з підказками через
hover-групи (`scope`). Панелі: `voice` — історія (🕘), `voice-settings` — ⚙: базове (мова, активатор,
стоп-слово, автозавершення, сигнал, озвучення, ↻) видно завжди, решта — у згортанні «Розширені»
(атом `advancedOpen`) групами «Розпізнавання», «Обробка команди», «Озвучення» (лише при
`tts: ready`: голос uk, голос en — як моделі, з ⬇ біля не завантажених; «Видалити озвучення»),
«Безпека й чати». «Озвучувати відповіді»: `tts: ready` — перемикач; `installing` — рядок
прогресу; інакше кнопка встановлення (при `error` — «Повторити»), під нею примітка про Piper і
GPL. Поки йде встановлення, слухач не виходить через `muted-exit`. У ⚙ пояснень
нема — біля поля кнопка ⓘ: натиск показує підказку під полем (одна на всі, 10 с, повторний
натиск закриває), на ПК ще й при наведенні. «Словник виправлень» у ⚙ — багаторядкове
`Input` (`rows`) над `glossary.txt`: тік, поки ⚙ відкрите, перечитує файл і міняє атом
`glossary` лише коли текст інший (інакше перерисовка стирала б недозбережене);
`glossaryStats` (`hooks/glossary.ts`) розбирає як `processor._load_file`. «Відкрити» —
`explorer.exe <файл>` (віддає асоційованому редактору й виходить).
«Згенерувати» — `$.agent.spawn` (Explore, opus) з `generatorPrompt` (`hooks/glossary.ts`):
контекст — почуте з 🕘, повідомлення людини цього чату, назви чатів з ListAgents, словник і
слова-підказки; відповідь — JSON у `turn.complete` агента (`e.answer`), лягає в атоми-чернетки
`glossaryDraft`/`hotwordsDraft` (на диск — лише Enter людини). Самодоповнення — інструмент
`mcp__voice-mod__add_term` (`$.tool.register` у boot): `checkRule` (варіант ≥ 3 літер, без
роздільників формату), без повторів, рядок із `# авто <дата>`; `autoTerms` у control.json
(типово true), вимкнено — deny і `tool.describe` ховає його за ToolSearch.

## Пастки API модів (виміряно)

- Відповідь субагента — у ВХОДІ `turn.complete` (`e.answer`), а не в результаті `next(e)`.
  Тестовий рушій віддає моду `$.agent.spawn` без `agentId` (лише `{model}`) — генератор
  впізнає свого агента ще й за формою відповіді (`isGeneratorReply`).
- `console` у модулі мода нема; відносний шлях `$.fs` рушій робить абсолютним, а `/` — `\`
  (для налагодження в тестах — писати у `${home}\\файл`).

- Події «цей чат на екрані» нема — власник голосу = сесія, де востаннє писали
  (фідбек: anthropics/claude-code#103529).
- У праву бічну панель застосунку моди не малюють; панелі різних модів — вкладки;
  заголовок панелі малює рамка застосунку.
- `Button` без тултипа; на мобільній поверхні нема `Input`/`Select`.
- `$.process.spawn` гине з модулем; `$.fs` без видалення файлів.
- Мод, увімкнений посеред сесії, `session.start` не отримує — `boot()` ще й з
  `prompt.submit`/`tool.call`. `$.ui.open` до під'єднання застосунку пише в
  транскрипт «no-surface».
- PowerShell 5.1 читає `.ps1` без BOM як ANSI — скрипти з кирилицею зберігати з BOM;
  `Set-Content -Encoding utf8` пише BOM, а JSON для слухача мусить бути без нього.
